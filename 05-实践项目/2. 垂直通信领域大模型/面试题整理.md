### 问题1：项目中怎么识别用户的问题是基础类 or 数学推导类问题？

**回答思路：** 从简单到复杂，展示你技术的演进过程和权衡考量。不要只说一个方法，要说出你考虑过的多种方案以及最终选择的理由。

“面试官您好，这是一个非常好的问题，因为它直接关系到我们系统后续处理流程的效率和准确性。对于问题类型的识别，我们主要探索并实践了三种方法，最终采用了混合策略。”

**1. 基于关键词规则的快速分类（基线方案）**
*   **做法：** 这是最直观、部署成本最低的方法。我们维护了两类关键词列表。
    *   **推导/计算类：** “推导”、“证明”、“计算”、“求解”、“画出...曲线”、“仿真”、“分析...性能”等。
    *   **概念类：** “什么是”、“解释一下”、“对比...和...”、“...的原理”、“...的定义”等。
*   **优点：** 实现简单，响应速度快，不占用模型资源。
*   **缺点：** 泛化能力差，容易误判。比如用户问“如何理解推导误码率的过程”，虽然含“推导”，但本质上是在问概念。

**2. 基于小模型的文本分类（进阶方案）**
*   **做法：** 我们将这个问题视为一个二分类任务。构建了一个标注好的数据集（约几千条），包含真实用户查询和对应的标签（概念类/推导类）。然后，我们微调了一个轻量级的模型，如 `BERT` 或 `RoBERTa`。
*   **优点：** 相比关键词规则，泛化能力显著提升，能理解更复杂的语义。
*   **缺点：** 需要额外的数据标注和模型维护成本，对于新出现的领域问题可能仍有偏差。

**3. 基于大模型的零样本/少样本分类（最终方案）**
*   **做法：** 这是我们在“智道”系统中最终采用的核心方法。我们利用系统底层的 LLM（如 GLM-4 或讯飞星火）本身，通过精心设计的 Prompt 来实现分类。
    *   **Prompt 示例：**
        ```
        请判断以下用户问题的类型。你必须且只能回答 "概念类" 或 "推导类"。

        [用户问题]: {user_query}

        [判断规则]:
        - 如果问题主要询问定义、原理、对比、解释，回答"概念类"。
        - 如果问题要求进行公式推导、数值计算、过程证明、代码仿真，回答"推导类"。

        [回答]:
        ```
*   **优点：**
    *   **零样本/少样本能力：** 无需大量标注数据，泛化能力最强，能很好地适应各种新颖的问法。
    *   **与现有架构融合：** 无需引入新的模型服务，直接复用系统已有的 LLM 资源，架构更简洁。
    *   **可解释性好：** 我们甚至可以让 LLM 在回答类型后，附上判断理由。

**总结：**
“我们最终采用的是**关键词规则 + LLM 分类**的混合策略。对于包含明确关键词的请求，我们先用规则快速分流，降低 LLM 的调用开销。对于模糊或复杂的查询，再交由 LLM 进行精准判断。这样既保证了效率，又确保了高准确率。”

### 面试官问题2：基础类问题用lora，数学推导类用gpro？NO！提示词优化模型的训练方式与训练过程的详细描述⬇️

**回答思路：** 这是一个典型的“陷阱题”，说明面试官听出你之前的表述有误。你需要先澄清事实，然后阐述正确的技术逻辑，展示你对技术细节的精确理解。

“感谢您的提问，我意识到我刚才的描述可能引起了误解，让我在这里澄清和详细说明一下。**LoRA 和 GPRO 并非分别用于处理不同的问题类型，而是在同一个模型的训练流程中扮演了不同阶段、不同作用的角色。**”

“我们用于提示词优化的 GLM-4-9B 模型，其训练流程是一个‘两步走’的策略：”

**第一步：基于 LoRA 的有监督微调（SFT）—— 打好基础**
*   **目标：** 让模型学会“如何说话”，掌握领域知识和基本的指令遵循能力。
*   **数据：** 我们准备了大量的高质量“指令-回答”对。其中既有**概念类问题**的回答（例如，“什么是奈奎斯特准则？” -> 补充上下文后的明确指令），也有**数学推导问题**的初步分解示例。
*   **作用：** 通过 SFT，模型首先学会了理解通信原理领域的语言风格、专业术语，并对如何拆解问题有了一个初步的模仿。LoRA 在这里的作用是**参数高效微调**，我们只需训练极少量的参数，就能将一个通用大模型适配到我们的专业领域，大大降低了训练成本和部署开销。

**第二步：基于 GPRO 的强化学习（RL）—— 精进技能**
*   **目标：** SFT 只能让模型“模仿”，但无法保证其拆解的步骤是**最优的、完整的、逻辑严谨的**。RL 的目标是让模型学会“思考”，主动优化拆解质量。
*   **针对对象：** GPRO 主要针对的是**数学推导类问题**的拆解能力进行优化。因为这类问题的结构性最强，对步骤的完整性和逻辑性要求最高，也是最能通过奖励函数来量化评估的。
*   **作用：** GPRO 通过一个奖励模型，告诉模型它生成的拆解步骤“好”还是“坏”。模型因此会不断调整自身，以生成更高质量的拆解序列。

**所以，正确的逻辑是：**
“我们先用 **LoRA+SFT**，让模型广泛学习各类问题的处理模式（打基础）；然后，再用 **GPRO+RL**，专门针对其中最关键、最复杂的数学推导拆解任务进行拔高和优化（练绝活）。它们是**串行关系、相辅相成**的，共同构成了我们提示词优化模型的完整能力。”

### 面试官问题3：为什么用强化学习，为什么用gpro，不是ppo dpo，然后gpro具体是怎么做的？

**回答思路：** 这是整个项目最硬核的技术点。你需要清晰地阐述 RL 的必要性，GPRO 相对于主流算法的优势，并且能讲出 GPRO 的具体实现细节，哪怕你说的 GPRO 是你基于项目理解自定义的，也要逻辑自洽。

**1. 为什么用强化学习（RL）？**
“核心原因在于：**SFT 只能教会模型‘是什么’，但 RL 能够教会模型‘什么是好’。**”
*   **SFT 的局限：** SFT 的目标是让模型的输出无限接近标注数据。但对于“问题拆解”这种开放性任务，一个问题的正确拆解方式可能不止一种，标注数据很难覆盖所有“好”的样本。更重要的是，SFT 无法直接优化我们关心的**结构性指标**，比如“步骤是否遗漏”、“逻辑是否连贯”。
*   **RL 的优势：** RL 允许我们定义一个**奖励函数**，这个函数可以精确地衡量我们对模型输出的期望。在我们的场景里，这个期望就是“步骤完整性”。我们可以设计一个奖励模型，来评估模型生成的步骤序列是否覆盖了所有关键节点，从而引导模型向这个方向优化。

**2. 为什么用 GPRO，而不是 PPO 或 DPO？**
“这是一个非常深入的技术选型问题。我们了解并评估了 PPO 和 DPO，但最终选择了一个更适合我们特定场景的 GPRO（Group Relative Policy Optimization，这里可以是你项目里对它的定义）。”

*   **对比 PPO (Proximal Policy Optimization)：**
    *   PPO 是一个非常通用的 RL 算法，但它训练过程相对复杂，对超参数（如 clip-range, KL 惩罚系数）敏感，训练稳定性有时难以保证。
    *   我们的任务是**序列生成**，奖励信号是稀疏的（只有在整个序列生成完才能评估）。PPO 在处理这种稀疏奖励时，效率不一定是最高的。

*   **对比 DPO (Direct Preference Optimization)：**
    *   DPO 非常适合处理**偏好数据**，即“答案 A 比答案 B 好”。它的训练过程更稳定，更像是 SFT。
    *   但 DPO 的局限在于，它依赖于成对的比较数据，并且难以直接优化一个**明确的、可计算的数值指标**（如我们的“步骤完整性得分”）。DPO 学到的是“相对好坏”，而我们的目标是让模型学会达到一个“绝对的高分”。

*   **选择 GPRO 的理由：**
    *   **GPRO 是我们针对“序列完整性”这一特定目标设计的优化策略。** 它的核心思想是**“基于群体的相对策略优化”**。
    *   **“群体”：** 对于同一个问题，我们让策略模型生成多个（比如 5 个）不同的拆解序列，形成一个“群体”。
    *   **“相对”：** 我们用一个强大的奖励模型（下文详述）为这个群体中的每个序列打分。然后，模型优化的目标不是去逼近一个绝对的高分，而是在这个群体内部，**让高分序列的生成概率相对高于低分序列**。
    *   **优势：** 这种方式避免了 PPO 的复杂性和不稳定性，也比 DPO 更能直接利用我们设计的数值化奖励函数。它通过内部比较，为模型提供了更密集、更稳定的优化信号。

**3. GPRO 具体是怎么做的？**
“GPRO 的实现关键在于三个部分：策略模型、奖励模型和优化循环。”

*   **① 策略模型：** 就是我们经过 SFT 的 GLM-4-9B-LoRA 模型。它的输入是原始问题，输出是一个拆解步骤序列。

*   **② 奖励模型：** 这是 GPRO 的核心。我们训练了一个专门的模型来评估步骤拆解的质量。它的输入是 `[用户问题, 模型生成的拆解序列]`，输出是一个 0-1 之间的分数。
    *   **奖励函数设计：**
        1.  **步骤覆盖度：** 我们预先通过人工或更强的模型（如 GPT-4）为一批核心问题构建了“黄金标准步骤”。奖励模型会将生成的步骤与黄金步骤进行对比，计算 Jaccard 相似度或 F1-Score。`R1 = F1-score(生成步骤, 黄金步骤)`。
        2.  **逻辑顺序性：** 我们利用领域知识图谱（也就是 GraphRAG 里的图）来构建一个步骤间的前后依赖关系。比如，必须先有“接收信号模型”才能有“判决门限”。奖励模型会检查生成序列的顺序是否符合这个依赖图。`R2 = 顺序正确性得分`。
        3.  **最终奖励：** `R = w1 * R1 + w2 * R2`。这个得分就是衡量步骤质量的“黄金标准”。

*   **③ 优化循环：**
    1.  从数据集中采样一个问题。
    2.  策略模型生成 K 个不同的拆解序列。
    3.  奖励模型为这 K 个序列打分，得到 `R1, R2, ..., Rk`。
    4.  根据 GPRO 的算法（可以理解为一种特殊的、基于得分的排序损失或对比损失），计算策略模型的损失。目标是让 `R` 高的序列对应的 log-prob 更高。
    5.  反向传播，更新策略模型的 LoRA 权重。
    6.  重复以上过程。

“通过这种方式，模型被引导着去生成那些既能覆盖所有关键点，又符合逻辑顺序的高质量拆解，这正是我们‘智道’系统解决复杂推导问题的基石。”

### 面试官问题4：RAG中的chunking文本分块是怎么做的？

**回答思路：** 同样，从通用到具体，展示你对不同技术方案的认知，并最终落脚到你的项目上，体现你的工程实践能力。

“在我们的‘智道’系统中，文本分块是知识预处理的关键一步，它直接影响了后续检索的召回效果。我们根据知识源的类型，采用了不同的分块策略。”

**1. 通用 RAG 的常见分块策略（我们评估过的方案）**
*   **固定大小分块：**
    *   **做法：** 将文本按固定的 token 数量（如 512 或 1024）切成块，块与块之间设置重叠（如 50 tokens）以保证上下文连续性。
    *   **优缺点：** 实现简单，但最大的问题是容易在语义不相关的地方（比如段落中间、公式中间）切断，破坏了信息的完整性。
*   **递归字符分割：**
    *   **做法：** 这是 LangChain 等框架中常用的方法。它会按照一个优先级列表来分割，比如优先按段落分割，其次按句子分割，最后再按固定字符数分割。
    *   **优缺点：** 相比固定大小，它能更好地保持语义单元的完整性，是目前比较主流和均衡的方案。
*   **语义分块：**
    *   **做法：** 利用 Embedding 模型计算句子或段落间的相似度，在相似度较低的地方进行切分。这能确保每个 chunk 内部的语义高度相关。
    *   **优缺点：** 效果最好，但计算成本最高，需要多次调用 Embedding 模型。

**2. 我们项目中“智道”的实际做法**
“我们的知识源主要是通信原理的教材、论文和技术文档，具有非常强的结构化特征。因此，我们没有采用纯粹的文本分块，而是**结构化解析 + 智能分块**的混合策略。”

*   **第一步：结构化解析**
    *   我们使用工具（如 `Unstructured`）或正则表达式，先将 PDF/Word 文档解析成结构化的数据，比如 `标题`、`章节`、`小节`、`定义`、`定理`、`公式`、`例题` 等。

*   **第二步：基于结构的智能分块**
    *   **以“小节”为基本单元：** 大部分情况下，我们以一个独立的“小节”作为一个 chunk。比如“2.3.1 高斯信道下的最佳接收机”这一整节，天然就是一个语义完整的知识单元。
    *   **特殊处理：**
        *   **定理/公式：** 一个定理及其证明过程会被打包成一个独立的 chunk。这确保了用户在检索某个定理时，能完整地看到其定义和推导。
        *   **长章节：** 如果某个章节过长，我们会在此章节内部，使用“递归字符分割”或“语义分块”进行二次切分。
        *   **关联性处理：** 我们会把一个“例题”和它所引用的“定理”或“公式”进行关联，在索引时可以作为一个组合 chunk 进行存储。

“这种做法的好处是，我们的 chunk 不是盲目的文本切片，而是带有**语义标签（如‘定理’、‘例题’）和逻辑结构**的知识单元。这为后续的 GraphRAG 构建和 Agent 的精准检索打下了坚实的基础。”

### 面试官问题5：项目中我看用到了Microsoft GraphRAG，这一块你觉得和普通的RAG有什么区别？

**回答思路：** 这是一个总结性的问题，考察你对 RAG 技术演进的理解。用清晰的对比表格，并紧密结合你的项目场景来阐述，会非常有说服力。

“面试官您好，选择 GraphRAG 是我们项目中的一个核心决策。它和普通 RAG 的区别，我认为主要体现在**知识表示、检索方式和推理能力**三个层面，而这些区别对于解决通信原理这类强逻辑、强关联的问题至关重要。”

| 特性维度 | 普通 RAG (Naive RAG) | Microsoft GraphRAG (我们的方案) |
| :--- | :--- | :--- |
| **1. 知识表示** | **扁平化的文本块**<br>将知识切分成独立的 chunk，每个 chunk 是一个孤立的文本片段。知识之间的关系是隐式的，依赖于向量空间的距离。 | **结构化的知识图谱**<br>将知识建模为“节点-边”图。节点是**实体**（如“香农公式”、“2ASK”），边是**关系**（如“是...的应用”、“推导出”、“引用了”）。知识关系是显式的、结构化的。 |
| **2. 检索机制** | **单阶语义相似度搜索**<br>用户提问 -> 向量化 -> 在向量数据库中找 Top-K 最相似的 chunk。 | **两阶检索：语义定位 + 图扩展**<br>1. **语义定位：** 同样是向量化提问，先找到最相关的种子节点。<br>2. **图扩展：** 以种子节点为起点，在图谱上进行多跳遍历（如 1-hop、2-hop 邻居），召回所有相关的上下文节点和边。 |
| **3. 上下文丰富度** | **“只见树木，不见森林”**<br>召回的上下文是孤立的，可能包含定义，但很难包含与该定义相关的推导、应用或其他关联概念。 | **“既见树木，又见森林”**<br>召回的上下文是一个**知识网络**。它不仅包含核心概念本身，还自动带上了它的前因后果、相互关联的知识，形成一个完整的逻辑链条。 |
| **4. 核心优势场景** | 适合**事实性问答**，如“香农公式是什么？”。 | 极大擅长**复杂推理、多跳问答和过程推导**，如“推导 2ASK 的误码率”。 |

**结合我们的项目场景来谈：**

“在‘智道’系统中，这种区别是决定性的。”

*   **当一个子问题是‘写出香农公式’时，** 普通 RAG 和 GraphRAG 可能都能召回公式本身。
*   **但当子问题是‘基于香农公式推导信道容量’时，** 区别就显现了。
    *   **普通 RAG** 可能会召回“香农公式”和“信道容量”两个独立的 chunk，但 Agent 需要自己猜测它们之间的推导关系。
    *   **我们的 GraphRAG** 在检索到“香农公式”节点后，会沿着“推导出”或“应用于”这样的边，**自动找到“高斯信道模型”、“互信息计算”等一系列中间节点**，并将这个完整的推导路径作为上下文提供给 Agent。

“这样一来，Agent 的推理负担被大大减轻。它不再需要从零散的文本片段中‘猜测’逻辑，而是在一个已经被梳理好的、结构化的知识网络上进行‘确认’和‘整合’。这显著提升了复杂问题求解的准确性和可靠性，也是我们‘智道’系统能够处理复杂推导任务的核心竞争力所在。”
