# LLM 后训练（Post‑training）概览

## 什么是 Post‑training？

- **Pre‑training（预训练）**：用大规模通用语料训练语言模型，让其掌握语言知识和基础能力。
- **Post‑training（后训练/对齐）**：在预训练基础上，进一步让模型：
  - 更符合人类偏好和安全规范；
  - 在特定任务上表现更好；
  - 在复杂推理场景下更稳定可靠。

在当前主流做法中，可粗略分为三大类路径：

1. **Tuning**：用监督数据直接微调参数（监督式后训练）。
2. **Reinforce**：用强化学习（奖励信号）对齐模型（RLHF、RLAIF 等）。
3. **Scaling**：在推理与解码阶段放大能力（搜索、推理链、采样和验证），通常不改变模型参数。

---

> 提示：在实际系统中，**Tuning / Reinforce** 是离线训练阶段完成的，而 **Scaling** 主要发生在**推理（inference）阶段**，但整体都属于“post‑training 使模型更可用”的范畴。

---
# 一、Scaling：推理与解码阶段的能力放大

Scaling 的重点：**不一定再改参数，而是通过更复杂、成本更高的推理/搜索/解码过程，挖掘模型已有潜力。**

可以看成是在 inference 阶段做“算力扩展”。

## 1. Search：在输出空间中搜索更好答案

### 1.1 Beam Search（束搜索）

- 每生成一步时，保留 K 条概率最高的候选序列；
- 不再只选单一最优 token，而是在 K 条路径上同时前进；
- 在机器翻译、摘要等任务上常见，可提升流畅性和全局连贯性。

### 1.2 Best-of-N / 多样生成 + 筛选

- 针对同一问题生成 N 个候选回答；
- 用规则、人类或另一个模型对这些候选评分；
- 选择得分最高的一条输出。

实践中：即使 N=4~8，也往往能明显提高数学题/代码题正确率。

### 1.3 Monte Carlo / MCTS 风格搜索

- 将模型当作“给出下一步动作的策略”，在决策问题（代码、规划、游戏）里：
  - 反复采样多个完整路径；
  - 计算每条路径的得分（成功与否、收益大小）；
  - 根据得分来回溯和更新搜索策略。
- 典型例子：AlphaGo 中的 MCTS，只是那里策略和价值网络是专门训练的网络；在 LLM 场景中是把 LLM 当作生成器和评估器的一部分。

### 1.4 Search Against Verifiers（对抗验证器搜索）

- 设计一个“验证器”（可以是规则、程序或另一个模型），检查输出是否：
  - 符合格式；
  - 逻辑自洽；
  - 满足题目约束；
- 生成 → 验证 → 不通过则重新生成或局部修改 → 再验证；
- 类似“生成—自动审稿—重写”的循环。

## 2. Reasoning：显式结构化推理

### 2.1 Chain-of-Thought（CoT，链式思维）

- 在提示词中要求模型“分步骤写出思考过程”，再给结论。
- 优势：
  - 比直接“给最终答案”更容易调动模型的推理能力；
  - 对数学、逻辑、复杂问答等效果明显。

### 2.2 Tree-of-Thoughts（ToT，树状思维）

- 把推理过程拆成多个阶段，每个阶段可以分叉出多种思路；
- 在这些分支上进行搜索（DFS/BFS 或启发式搜索）：
  - 例如“先考虑 A/B/C 三种方案，再分别细化”，之后选择最有希望的分支继续展开；
- 对长链规划和开放问题（如解谜、长篇写作）表现更好。

### 2.3 Self-Consistency / Consistency Decoding

- 对同一问题，多次让模型用 CoT 推理，得到多条推理链和多个答案；
- 对答案做投票或聚类，选择最一致的结论；
- 直觉：如果多次独立思考都指向同一结论，该结论更可靠。

---

## 3. Decoding：更聪明的解码策略

### 3.1 动态采样与温度调节

- Top‑k、Top‑p、温度等超参直接影响：
  - 创造力/多样性；
  - 稳定性/保守程度。
- 动态策略：根据任务类型或中间状态调整这些参数，比如：
  - 写小说时温度高、Top‑p 大；
  - 写代码/做数学题时更保守，温度低、Top‑p 小甚至贪心。

### 3.2 约束解码（Constrained Decoding）

- 在解码过程中施加硬约束：
  - JSON/XML 结构合法；
  - 满足正则表达式或语法；
  - 不出现敏感词等。
- 常通过有限状态机、语法解析器或特定库来实现（如 constrained beam search）。

### 3.3 多轮生成‑检查‑修改解码

- 不是一次性输出，而是：
  - 第一次粗生成；
  - 用程序或另一个模型检查错误（语法、逻辑、风格）；
  - 在错误位置做局部重写；
- 类似多轮稿件修改，提高最终质量。

---

## 4. Confidence：置信度与输出可靠性

### 4.1 置信度估计

- 为输出或部分 token 计算“自信程度”：
  - 利用概率分布熵；
  - 利用多个采样结果的一致性；
  - 训练专门的不确定性估计模型。
- 应用：
  - 置信度低时提示用户“答案不一定可靠”；
  - 或触发备用流程（外部搜索、工具调用、人工审核）。

### 4.2 验证器（Verifier）与校验模型

- 使用专门的模型/规则对输出进一步审查：
  - 事实性（事实核查）；
  - 安全性（有害内容、隐私泄露）；
  - 逻辑一致性（如形式验证器、测试用例）。
- 可与 Search 结合，形成“生成→验证→搜索更好候选”的闭环。

### 4.3 拒答或工具切换

- 当置信度不足或违反安全规则时：
  - 选择拒绝回答；
  - 或调用外部工具（检索、计算器、代码执行环境）来补充信息。

# 二、Tuning：监督式后训练

Tuning 的核心思想：**用人工或自动构造的标注数据，直接更新模型参数**。不需要在线交互式奖励，只依赖离线数据。

### 1. 全参数微调（End-to-End Fine-tuning）

- 直接对模型全部参数进行梯度更新。
- 常见应用：
  - 指令微调（Instruction Tuning）：用“指令 + 期望回答”的数据，让模型学会遵循自然语言指令。
  - 领域适配（医疗、法律、金融等专业语料）。
- 优点：效果强，能明显改变模型行为。
- 缺点：算力和存储成本高，对大模型不够经济。

### 2. 参数高效微调（PEFT）

在大模型上，只改一小部分参数：

- **LoRA / Low-Rank Adaptation**：在权重矩阵旁边加低秩更新矩阵，训练时只更新这部分。
- **Adapters**：在层之间插入小模块，只训练插入模块。
- **Prompt-tuning / Prefix-tuning**：训练一小段可学习的“虚拟 prompt”，主模型参数冻结。

特点：

- 对资源友好，易于在多个任务上复用。
- 可维护一组“多任务/多客户适配头”。

### 3. 知识蒸馏（Distillation）

- 用一个强模型（Teacher）生成标签/解释，再用这些数据训练小模型（Student）。
- 目标：
  - 让小模型模仿大模型的能力；
  - 减小推理成本（部署在端侧、移动端）。

### 4. 离线策略与行为克隆（Offline Policy / Behavior Cloning）

- 收集大量“人类写的优质回答”或“旧模型+人工筛选的回答日志”。
- 把这些作为监督标签，让模型“模仿”这些行为：
  - **Behavior Cloning**：类似模仿学习。
  - **Self-Critique**：模型先给出答案，再自评/修改，把“原始回答 + 自我批注结果”一起用来训练。

优点：只用离线数据，不需要在线与人持续交互，工程上可控性好。

# 三、Reinforce：强化学习式对齐

Reinforce 的核心：把“对齐人类偏好”视为一个 **强化学习（RL）** 问题。

## 1. 主要步骤

1. **收集偏好数据**
   - 让模型对同一问题生成多个回答；
   - 人类（或规则）给出偏好标注：哪个更好、是否安全、是否有害等。

2. **训练奖励模型（Reward Model, RM）**
   - RM 输入：问题 + 模型回答；
   - 输出：一个标量 reward 或排序分数；
   - RM 学习尽量与人类偏好一致。

3. **用 RL 优化策略模型（Policy Model）**
   - Policy 输出文本，RM 给 reward；
   - 用 RL 算法调整 Policy，使高 reward 答案概率更大。

## 2. 代表方法与算法

- **RLHF（Reinforcement Learning from Human Feedback）**  
  最经典的一条线：人类标注偏好 → 奖励模型 → PPO 等算法做策略优化。

- **RLAIF（RL from AI Feedback）**  
  用其它模型代替人类给偏好反馈，降低人工成本。

- **DPO（Direct Preference Optimization）**  
  不显式训练奖励模型，直接在“好/坏回答对”上优化策略，使其更偏向“好回答”。

- **具体算法**  
  - TRPO / PPO / Vanilla Policy Gradient / REINFORCE / GRPO 等传统策略梯度方法；
  - 结合文本生成特点，常有各种稳定性和安全性的工程改造。

## 3. 特点

- 更直接地聚焦“人类偏好”和“安全约束”；
- 可显著改变模型行为，但训练复杂、超参敏感；
- 常用在已经过指令微调的基础模型上做“最后一公里”的对齐。

# 四、整体对比与实战建议

可以用一句话概括三类方法的定位：

- **Tuning：** 用「已有标注数据」调整参数，让模型学会执行指令、适配领域。
- **Reinforce：** 用「奖励信号 / 偏好反馈」进一步对齐行为和安全边界。
- **Scaling：** 在「推理与解码阶段」投入更多算力，通过搜索、结构化推理和验证，把现有能力发挥到更极致。

在实战项目里，常见的组合是：

1. 预训练基础模型 → 指令微调 (Tuning) → RLHF 或 DPO (Reinforce)；
2. 部署侧使用 CoT + Self‑Consistency + Best‑of‑N + 验证器 等一系列 Scaling 技术来提升可靠性。
