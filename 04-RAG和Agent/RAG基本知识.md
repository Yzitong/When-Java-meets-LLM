# RAG基本知识

**RAG（检索增强生成）** 是一种结合 **信息检索** 和 **文本生成** 的技术，旨在通过引入外部知识库提升生成模型的事实准确性、相关性和多样性。其核心思想是：在生成答案前，先从大规模文档库中检索相关上下文，再基于检索结果生成最终输出。RAG就像是让大模型开卷考试，不必再死记硬背所有知识，而是根据用户问题先去查参考书，然后再进行回复。

RAG技术与模型微调都是典型的解决大模型幻觉问题的方式，但是相比于模型微调，RAG技术更适合于**“动态数据”**。

## 一、信息检索（RAG）的基本流程

RAG 是 "Retrieval-Augmented Generation" 的缩写，中文可以翻译为“检索增强生成”。它是一种结合了信息检索和自然语言生成的技术框架，名称的含义为：

- 检索：从知识库（数据库或内存）访问和检索信息。
- 增强：通过附加信息或上下文来增强或丰富文本生成过程。
- 生成：创造或生成文本的过程。

### 1.1 数据准备阶段

数据准备一般是一个离线的过程，主要是将私域数据向量化后构建索引并存入数据库的过程。主要包括:数据提取、文本分割、向量化、数据入库等环节。

**1.数据提取**

- 数据加载:包括多格式数据加载、不同数据源获取等，根据数据自身情况，将数据处理为同一个范式。
- 数据处理:包括数据过滤、压缩、格式化等。
- 元数据获取:提取数据中关键信息，例如文件名、Title、时间等。

**2.文本分割(chunking)**

文本分割主要考虑两个因素:

1) **embedding模型的Tokens限制情况;**
2) **语义完整性对整体的检索效果的影响。**

- 一些常见的文本分割方式如下:
  - **句分割:**  以”句”的粒度进行切分，保留一个句子的完整语义。常见切分符包括:句号、感叹号、问号、换行符等。
  - **固定长度分割:**根据embedding模型的token长度限制，将文本分割为固定长度(例如256/512个tokens)，这种切分方式会损失很多语义信息，一般通过在头尾增加一定冗余量来缓解。

**3.向量化(embedding)**

向量化是一个将文本数据转化为向量矩阵的过程，该过程会直接影响到后续检索的效果。

- embedding可以理解为一种向量化的过程，但它不仅仅是简单的向量化。
- Embedding的核心思想是将高维稀疏特征转化为低维稠密特征的“压缩”方法。这种转化不是简单地将数据映射到一个向量空间，而是通过模型自动学习如何有效地表示原始数据的关键特征，从而使得这些向量具有一定的语义信息和数学可操作性(如向量间的距离、夹角等可以反映原始数据之间的关系)。

**4.数据入库**

数据入库是数据向量化后构建索引，并写入数据库的过程。

- 核心动作：构建索引（存储分割后的文本块及其向量嵌入的键值对）、写入数据库。
- 常见向量数据库：Chroma、ADB、Faiss 等。

### 1.2 应用阶段

应用阶段核心是根据用户提问召回相关知识并融入 Prompt，辅助大模型生成答案，关键环节包括数据检索、注入 Prompt。

**1. 数据检索**

数据检索可选择单一方式或多种方式融合，核心目标是提升**召回率**。

- 常见检索方法：相似性检索、全文检索。

**（1）相似性检索**

- 核心逻辑：计算查询向量与存储向量的相似性得分，返回高分记录。
- 常见计算方法：余弦相似性、欧氏距离、曼哈顿距离等。

**（2）全文检索**

- 核心依赖：**倒排索引**（Inverted Index）这一经典数据结构。
- 倒排索引核心原理：
  1. 存储方式反转：提取文档关键词（Token）建立索引条目，而非按原始文档顺序存储。
     - 示例：[信息检索——简单易懂的倒排索引（原理+例子）-CSDN博客](https://blog.csdn.net/qq_43403025/article/details/114779166)。
  2. 加速查询过程：用户搜索关键词时，直接定位包含该词的文档，避免遍历所有文档。

**2. 注入Prompt**

Prompt 是大模型的直接输入，直接影响输出准确率。

- RAG 场景下 Prompt 核心构成：任务描述、背景知识（检索所得）、任务指令（用户提问）。
- 优化方向：可根据任务场景和大模型性能，加入其他指令优化输出。

## 二、Query Translation查询翻译

参考文章：[RAG从入门到精通 | Query Translation（查询翻译）-CSDN博客](https://blog.csdn.net/star_nwe/article/details/145223837)

在机器学习领域有一句经典的话：Garbage in，Garbage out

这句话也是适合于 RAG，因为我们现在检索的原理就是根据用户的 Query（也就是 Question）的语义去检索相关的文档。

但是我们不能指望所有的用户都能清楚地描述自己的 Query，如果用户写了一句模棱两可的 Query 或者是一个复杂的 Query，那么检索到的文档也将是模棱两可或者难以准确检索，进而导致 LLM 的回答就不准确。

Query Translation查询翻译的方法可以分为四大类：

- Re-written（改写）
- Step-back question（优化问题） 
- sub-question（分解问题）
- HyDE（假设性文档嵌入）

![image-20251108220952657](https://raw.githubusercontent.com/Yzitong/When-Java-meets-LLM/main/images/image-20251108220952657.png)

### 2.1 Re-written（改写）

Re-written 是指**对原始查询进行语义重写**，保持核心意思不变，但调整语言表述，使得问题更易被知识库或检索系统处理。

**应用场景：**

原始问题语言模糊或表述不清。
需要通过不同的表述来优化检索匹配。

**示例：**

原始问题：“Python 的用法？”
Re-written：“Python 编程语言的常见使用场景是什么？”
效果：改写后的问题更具体，更容易检索到高质量答案。

**常见方法：**

- **Multi-Query：**在检索阶段针对同一个问题生成多个不同的查询，通过这些查询去检索知识库，以获得更全面或相关的文档集合。
- **RAG Fusion：**一种在生成阶段融合检索结果的策略。它关注的是如何从多个检索到的文档中综合信息，以生成高质量的回答。

### 2.2 sub-question（分解问题）

基本思路是：将复杂的问题拆解为多个独立的子问题，每个子问题可以单独处理。最终通过聚合子问题的答案来生成完整的回答。

**应用场景**：

- 多跳问题（需要跨多个知识点回答）。
- 包含逻辑操作或条件限制的问题。

**示例**：

- 原始问题：*“诺贝尔奖得主中，谁既是科学家又是文学家？”*
- Sub-question：

1. “诺贝尔奖得主中有哪些科学家？”
2. “诺贝尔奖得主中有哪些文学家？”
3. “有哪些人既是科学家又是文学家？”

### 2.3 Step-back question（优化问题） 

这是考虑数据库中的内容不够全面时的场景，如果在检索和回答过程中，意识到当前的问题太具体或难以直接回答时，退一步改问一个更广泛、更概括性的问题，可以获取更大的上下文信息。

**应用场景**：

- 当前查询太具体，无法直接匹配知识库内容。
- 检索结果中没有足够的信息来回答原始问题。

**示例**：

- 原始问题：*“爱因斯坦在 1921 年诺贝尔奖颁奖仪式上的具体演讲内容是什么？”*
- Step-back Question：*“爱因斯坦为什么获得 1921 年诺贝尔奖？”*
- 效果：通过回答更概括的问题，间接获取相关的上下文信息，为后续回答具体问题提供支持。

**优点**：

- 提高了检索的召回率和上下文覆盖率。
- 适用于数据稀疏或回答难度较高的场景。

**挑战**：

- 如何自动判断何时需要“退一步”？
- 退回的问题是否仍能与原始问题保持语义相关性。

### 2.4 HyDE（假设性文档嵌入）

HyDE（Hypothetical Document Embedding） 是一种用于 Query Translation 的创新方法，特别适用于 RAG 系统中的复杂问题处理。HyDE 的核心思想是通过生成“假设文档”（Hypothetical Document），将查询从抽象的自然语言问题转化为检索系统能够高效处理的表示。

也就是说，**既然查询和文档的向量不好匹配，那我们为什么不先根据查询“创造”一个理想的、假设的文档，然后用这个“假设文档”作为桥梁去搜索呢？**

**核心直觉**：即使这个生成的文档在细节上可能不准确，但它会**在语义上和语言风格上非常接近真正相关的文档**。用它作为搜索的“探针”，效果会比直接用原始的、简短的查询好得多。

1. **生成假设文档**：
   - 使用一个**指令微调过的大型语言模型（如 GPT-3, InstructGPT 等）**。
   - 给模型一个指令，例如：`“请根据以下问题，生成一个权威的、详细的答案段落。”`
   - 然后将用户的查询（例如：“如何给自行车轮胎打气？”）输入给模型。
   - 模型会生成一个假设的答案，比如：“给自行车轮胎打气需要几个步骤。首先，您需要找到气门嘴... 确保使用正确的气门嘴适配器... 建议使用胎压计监测压力，通常侧壁会标注推荐的 PSI 值...”
   - **关键点**：我们并不关心这个生成答案的**事实正确性**（它可能说错细节），我们只关心它的**语义和风格**。它现在已经从一个短查询，变成了一个在主题、词汇、结构上都与真实目标文档相似的“文档”了。
2. **嵌入与检索**：
   - 将这个生成的、高质量的“假设文档”通过一个**嵌入模型**（如 Contriever, OpenAI Embeddings 等）转换成向量。这个向量就是 **HyDE 嵌入**。
   - 用这个 HyDE 嵌入向量去向量数据库中执行相似性搜索。
   - 因为 HyDE 嵌入在向量空间中与真实的相关文档靠得更近，所以检索的准确率会显著提高。
