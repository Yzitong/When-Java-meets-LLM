# Agent基础知识

## Agent 的核心价值：为什么需要 “智能体”？

大模型天生存在一个问题：**无法主动更新知识**，导致容易产生 “事实幻觉”（输出与真实情况不符的内容）。

- **RAG（检索增强生成）可以在一定程度上解决这个问题**：
  相当于给大模型配了 “本地知识库”。当大模型要回答问题时，会先在**本地知识库**里搜索，检查 “提示中的信息是否真实”：
  - 如果真实，就直接用这些知识生成回答；
  - 如果不真实，就用知识库的内容修正错误。
- **Agent 的必要性**：
  若**本地知识库找不到相关信息**（比如需要实时数据、最新知识），就需要 “调用外部工具”（如网络搜索、数学计算器、编程环境等）来补充信息。这时候就需要 Agent—— 它是 “能调用各类工具的执行者”。

具体来说，Agent 的必要性体现在：

**1. 大模型 “被动”，Agent 能 “主动规划”**

大模型是 “输入 - 输出” 的被动工具：你问 “如何做一份竞品分析报告”，它只能输出 “步骤清单”（如 1. 确定竞品；2. 收集数据…），但无法主动推进任何一步。
而 Agent 能**自主拆解任务并执行**：例如你说 “帮我做 A 产品的竞品分析”，Agent 会自动：① 确定 3 个核心竞品（调用行业数据库）；② 收集这 3 个竞品的价格、功能数据（调用爬虫工具）；③ 生成对比表格（调用 Excel 工具）；④ 撰写分析结论 —— 全程无需你手动干预。

**2. 大模型 “无工具”，Agent 能 “扩展能力”**

大模型自身没有 “实时交互、计算、操作” 能力：它不能查实时天气、不能订机票、不能算复杂数据、不能控制设备。
而 Agent 是 “工具管理者”：通过调用外部工具（API、软件、硬件），Agent 能实现大模型的 “能力外延”：

- 例如 “帮我订明天去上海的机票”：Agent 会调用 “机票预订 API” 查余票、选航班、完成下单；
- 例如 “帮我分析近 3 年公司的财务趋势”：Agent 会调用 “Excel 工具” 读取数据、计算增长率、生成折线图。

## Agent的定义与结构

Agent 是一种**能自主决策、主动行动以达成目标**的智能实体（基于大模型构建），可以 “感知环境、理解需求，然后采取行动完成任务”。

从结构上看，Agent 像一个 “微型智能系统”，分为三部分：

- **Perception（输入 / 感知层）**：
  相当于 “感官”，负责接收外界信息。比如通过文字对话、传感器（摄像头、麦克风）、物联网设备等，感知外部世界的需求或变化。
- **Brain（大脑 / 决策层）**：
  是 Agent 的核心，包含**信息存储、记忆、知识库、规划决策系统**。它会处理 “感知层” 收到的信息，结合自身知识，规划出 “该做哪些步骤、调用什么工具”。
- **Action（行动 / 执行层）**：
  相当于 “手脚”，根据 “大脑” 的决策去做事。主要是**调用外部工具的 API**（如让搜索引擎查资料、让编程工具跑代码），或者直接控制物理设备（如机器人的电机、智能家居的开关）。

## Agent的核心功能

Agent 像一个 **“多功能接口”**—— 能连接并使用各类工具，根据用户需求规划 “解决问题的步骤”，决定调用哪些工具来完成任务。

**组成公式**：**Agent = 大语言模型 + 规划 + 记忆 + 工具使用**。

1. **规划（Planning）：**最核心最关键的部分，负责**拆解复杂任务为可执行的子任务**，并规划执行任务的流程。同时 Agent 还会对任务执行的过程进行思考和反思，决定是否继续执行任务，并**改进决策策略**。
   - 任务分解：将复杂任务分解为可执行的子任务，让大模型逐步解决，例如将订外卖分解为选择餐厅 + 选择菜品两步。关键技术例如 CoT、LLM+P 等。
   - 反思：Agent 通过完善过去的行动决策和纠正以前的错误来不断改进。关键技术例如 React、Reflexion 等。
2. **记忆（Memory）**：包括短期记忆和长期记忆，用于存储会话上下文和业务数据等信息，来优化未来行为。
   - 短时记忆：即上下文学习，**由于受到 Transformer 上下文窗口长度的限制，它是短暂的和有限的**。
   - 长期记忆：则可对应为**外部的向量数据存储**，Agent 可在查询时引用，并可通过快速检索进行访问。
3. **工具使用（Tools）**：通过调用外部工具（如 API、插件）扩展 Agent 的能力，如文档解析、代码编译等。
